# 🔐 Botium Security Audit

> **Security Audit & Compliance Assessment** — Fictional retail company case study  
> Frameworks: PCI DSS v4.0 · GDPR · SOC 2 Type II · NIST CSF · ISO 27001

---

## 📋 Project Overview

This project simulates a full-scope **security audit engagement** for Botium, a fictional mid-size retail company operating in the EU. The audit covers security control assessment, compliance gap analysis, risk prioritisation, and actionable remediation recommendations — structured as a professional deliverable for stakeholder presentation.

The project was developed as part of a **GRC portfolio**, demonstrating practical skills in audit methodology, control testing, compliance mapping, and executive reporting.

---

## 🎯 Objectives

- Assess Botium's security posture against industry-recognised frameworks
- Identify control gaps and compliance deficiencies across PCI DSS, GDPR, and SOC 2
- Evaluate risk levels and prioritise findings by criticality
- Deliver an executive-ready report with structured remediation roadmap

---

## 🧩 Frameworks Applied

| Framework | Version | Application |
|---|---|---|
| **PCI DSS** | v4.0 | Payment data environment controls |
| **GDPR** | EU 2016/679 | Data protection and privacy compliance |
| **SOC 2** | Type II | Trust Service Criteria — Security & Availability |
| **NIST CSF** | v2.0 | Security posture baseline and gap mapping |
| **ISO 27001** | 2022 | Information security control reference |

---

## 🔍 Audit Scope

- In-scope systems: e-commerce platform, payment processing, customer data storage, internal network
- In-scope processes: access management, data handling, incident response, vendor management
- Out-of-scope: physical security, HR processes, non-digital assets

## 🛠️ Methodology

1. **Scoping** — Define audit boundaries, applicable frameworks, and stakeholder requirements
2. **Evidence Collection** — Request and review policies, configurations, and process documentation
3. **Control Testing** — Assess design adequacy and operating effectiveness of key controls
4. **Gap Analysis** — Map findings against framework requirements; identify missing or deficient controls
5. **Risk Rating** — Prioritise findings using a severity matrix (Critical / High / Medium / Low)
6. **Reporting** — Deliver executive summary and detailed findings with remediation recommendations
